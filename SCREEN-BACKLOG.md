# Screen implementation backlog

This backlog is the execution contract for the Figma-to-SwiftUI work. It is intentionally separate from the design brief so each screen can be completed, reviewed and signed off independently.

## Status and ordering

All stories are **Backlog**. The order is dependency-first: shell and tokens → core menu-bar surfaces → onboarding/helper lifecycle → settings/preferences → telemetry variants → errors and maintenance → accessibility verification. A row can move to **In progress** only after its dependencies are available; it can move to **Done** only after the Definition of Done below.

### Definition of Done for every row

1. Implement the frame's behaviour and visual state in the named SwiftUI surface; no placeholder content remains.
2. Build successfully with no introduced compiler warnings/errors relevant to the story.
3. Render the view in the target macOS environment/simulator at the Figma frame size or equivalent native window size.
4. Compare the render against the linked Figma node, correct material differences, and record the verification evidence.
5. Exercise every entry/exit path in the row, including keyboard/VoiceOver and disabled/loading/error states where listed.
6. Confirm shared preferences/telemetry/helper state does not regress already completed stories.

### File shorthand

`DS` = `DesignSystem/Components` and `DesignSystem/Theme`; `MB` = `Features/MenuBar`; `ON` = `Features/Onboarding`; `SET` = `Features/Settings`; `UP` = planned `Features/Updates`; `AL` = planned `Features/Alerts`; `SVC` = `Services`; `MODEL` = `Models`.
